# Draw Gyotong Design System

> 디자인 언어: **노선도와 안내사인 (Transit Cartography & Signage)**
>
> 지도는 인쇄된 노선도처럼, UI는 역 안내판처럼 만든다. 화면에서 가장 화려한 것은 UI가 아니라 플레이어가 그린 노선이어야 한다.

## 1. 핵심 원칙

1. **채도는 노선에만 쓴다.** 지도와 UI는 무채색에 가깝게 두고, 강한 색은 노선 고유 색과 신호 색(주의·위험·정보·정상)에만 허용한다.
2. **UI는 안내판이다.** 평평한 면, 굵은 상단 띠, 큰 글자, 각진 모서리를 쓴다. 장식이 아니라 즉시 읽히는 정보로 위계를 만든다.
3. **활성은 반전으로 표시한다.** 눌린 도구와 주 행동은 색을 칠하지 않고 먹/종이를 뒤집어 표시한다. 그래서 노선 색과 경쟁하지 않는다.
4. **모드마다 재질이 다르다.** 관리는 안내사인, 기획은 트레이싱지 위 파란 연필, 공사는 도면과 공사 표식이다. 지금 어느 모드인지 색이 아니라 표면의 문법으로 알 수 있어야 한다.
5. **같은 대상은 어디서나 같은 기호로 그린다.** 노선 기호, 역 기호, 상태 표식은 지도, inspector, 후보 chooser, 통계, 자동 노선도에서 같은 모양을 쓴다.

## 2. 화면의 세 층

1. **Map field**: 노선, 역, 열차, 차량기지, 수요, 지형, 공사와 계획을 보여 주는 주 작업면. 인쇄 지도처럼 낮은 대비로 둔다.
2. **Control rail**: 모드, 도구, 시간 제어처럼 자주 쓰며 짧게 유지되는 명령 영역. 안내판 띠처럼 얇고 단단하게 만든다.
3. **Context surface**: 현재 선택 객체나 작업의 세부 정보, 검토, 확정을 위한 일시적 표면. 역명판처럼 상단 띠와 큰 제목을 가진다.

컨테이너를 여러 장의 카드로 쪼개지 않는다. 하나의 연속된 패널 안에서 상단 띠, 제목, 구획선, 데이터 행, 그룹 레이블로 계층을 만든다. 배경색 변화는 깊이 표현이 아니라 실제 영역 분리 또는 상호작용 상태에만 사용한다.

## 3. 테마

두 가지 테마를 지원하며 기본값은 **종이(paper)** 다.

| 테마 | 성격 | 용도 |
| --- | --- | --- |
| 종이 `paper` (기본) | 밝은 종이 지도 + 먹색 글자 | 주간, 야외 반사, 기본 플레이 |
| 먹 `ink` | 어두운 먹 지도 + 종이색 글자 | 야간, 저조도, 사용자 선호 |

- 테마는 `설정 → 화면 → 지도 테마`에서 전환한다. 기기 설정으로 저장하며 세이브 슬롯에 넣지 않는다.
- 루트에 `data-theme="paper" | "ink"`를 두고 모든 색은 아래 토큰으로만 참조한다. 컴포넌트에 테마별 분기 색을 직접 쓰지 않는다.
- 상태 표시줄 색(`meta[name=theme-color]`)은 테마를 적용할 때마다 현재 `--surface-0`으로 맞춘다(`syncThemeColorMeta`). `index.html`의 초기값은 종이 테마 `--surface-0`이다.
- 전환은 즉시 적용하며 draft, 선택, 열린 표면, 지도 시야를 유지한다.
- 지도 타일, 지형·철도 오버레이, 자동 노선도 SVG, 내보내기 이미지까지 같은 테마를 따른다.
- 두 테마 모두 같은 형태 문법(반전, 상단 띠, 기호)을 쓴다. 테마는 명도만 바꾸고 언어를 바꾸지 않는다.

### 4.4 색상 사용 규칙

- 노선 고유 색은 시뮬레이션 데이터다. UI 장식이나 버튼에 노선 색을 빌려 쓰지 않는다. 단, 그 노선을 대상으로 하는 표면의 상단 띠와 노선 기호에는 쓴다.
- 노선 색 위의 글자는 대비를 계산해 `#FFFFFF` 또는 `#15171A` 중 하나를 자동으로 고른다.
- 지도 위 노선은 테마 바탕색의 casing(테두리)으로 감싸 어떤 노선 색도 바탕 대비 3:1 이상을 확보한다.
- 신호 색은 정상 상태에 쓰지 않는다. `ok`는 상태 표식에만 쓰고 넓은 면에 칠하지 않는다.
- `caution`은 노란 면 위에 먹 글자를 쓰는 안내판 방식으로만 면에 칠한다. 노란 글자를 종이 바탕에 직접 쓰지 않는다(`caution-text` 사용).
- 상태는 색만으로 구분하지 않는다. 아이콘, 레이블, 선 모양, 패턴 중 하나 이상을 반드시 병행한다.
- 그라디언트는 연속 수치 범례(인구 밀도, 혼잡도)에만 허용한다. 공사 빗금은 그라디언트가 아니라 패턴 기호로 취급하며 공사 상태에만 쓴다.

## 5. 타이포그래피와 숫자

```css
font-family: "Pretendard Variable", Pretendard, "Noto Sans KR", system-ui, sans-serif;
```

앱 패키지에 폰트를 포함하지 않았다면 네트워크 폰트 다운로드에 의존하지 않는다. 숫자는 `font-variant-numeric: tabular-nums`를 기본으로 한다.

크기는 가로 모드 폰(CSS 폭 640–960px)을 기준으로 정한다. 데스크톱이나 태블릿에서도 같은 값을 쓰며 화면이 넓다고 키우지 않는다.

| 역할 | 크기 / 행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| Display | `22 / 28` | 800 | 전체 화면 제목, 중요 확인 제목 |
| Sign | `18 / 24` | 800 | inspector 객체명(역명·노선명). 역명판처럼 크게 |
| Section | `12 / 16` | 800 | 패널 내부 구획 레이블 (`--text-2`) |
| Body | `14 / 20` | 600 | 기본 설명, 데이터 행, 도구명 |
| Label | `12 / 16` | 700 | 필드명, 짧은 상태, 단위 |
| Micro | `11 / 14` | 600 | 범례, 지도 보조 레이블, compact 레일 도구명 (최소 크기) |
| Metric | `18 / 22` | 800, tabular | 자금, 시간, 주요 KPI |

규칙:

- 핵심 숫자는 단위와 함께 읽혀야 한다. `12,450억`, `4.2 km`, `03:40`, `87%`처럼 형식을 일관되게 한다.
- 같은 열의 숫자는 오른쪽 정렬한다.
- 영문 대문자 eyebrow는 쓰지 않는다. 구획 레이블은 한국어 Section 스타일로 쓴다.
- 역명 아래 보조 표기(영문 역명 등)를 쓸 경우 Label 크기 `--text-2`로 한 줄만 둔다.
- 글자를 작게만 줄여 밀도를 높이지 않는다. 중복 문구와 불필요한 컨테이너를 제거해 밀도를 만든다.

## 6. 간격, 형태, 깊이

4px 기반 스케일을 사용한다: `4, 8, 12, 16, 24, 32`.

- 컨트롤 내부: 가로 `12`, 세로 `8`
- 주 행동 버튼(확정·취소·HUD 정보판): 높이 `48`
- 도구·목록 행, 보조 버튼: 높이 `44`
- 데이터 행(읽기 전용): 높이 `30–36`
- 패널 내부 구획: `12–16`
- 화면 가장자리 및 safe area: `max(12px, env(safe-area-inset-*))`
- 관련 요소 간격은 `4–8`, 그룹 간격은 `12–16`

형태는 안내판처럼 각지게 한다.

- 모든 버튼·입력·패널·다이얼로그: radius `2px`
- 노선 기호: radius `2px` (정사각형)
- 원형은 지도 위 역 기호, 상태 점, 라디오 입력에만 쓴다. pill 형태 버튼·탭·태그는 쓰지 않는다.
- 선 두께: 구획선 `1px`, 패널 외곽선 `1px --edge`, 상단 띠 `4px`, 강조 구분선(액션 바 위) `2px --text-1`

깊이는 그림자가 아니라 외곽선으로 만든다.

- 지도 위 표면은 `1px --edge` 외곽선으로 지도와 분리한다. 그림자는 쓰지 않는다.
- 겹치는 일시 표면(후보 chooser, tooltip)에 한해 `0 2px 0 rgba(0,0,0,.18)` 한 단계의 단단한 그림자를 허용한다. blur 그림자, glassmorphism, 반투명 패널, glow는 금지한다.

## 7. 기본 시각 자산

### 7.1 노선 기호 (Line mark)

모든 화면에서 노선을 식별하는 단일 자산이다.

- 정사각형, radius `2px`, 노선 색 면 + 자동 대비 글자(노선 번호 또는 2자 약칭), 굵기 800
- 크기: `24`(inspector 헤더), `20`(목록·행), `16`(compact·chooser 보조)
- 급행 계통은 노선 기호 오른쪽에 먹색 `급행` 태그를 붙인다. 기호 자체의 색을 바꾸지 않는다.
- 공사 중인 노선은 기호 테두리를 `caution` 점선 `2px`로 둘러 표시한다.
- 기획안 노선은 면을 비우고 노선 색 점선 테두리로 표시한다.

### 7.2 상태 태그

직사각형 radius `2px`, 높이 `20`, 아이콘 + 짧은 텍스트. 색은 테두리·아이콘에 쓰고 면은 `--surface-0`을 유지한다(주의 상태 제외).

| 상태 | 표식 | 형태 |
| --- | --- | --- |
| 운행 | `●` + `운행` | `ok` 아이콘 |
| 공사 | 빗금 칩 + `공사` | `caution` 면 + 먹 글자 |
| 기획 | `◌` + `기획` | `info` 점선 테두리 |
| 중지 | `‖` + `중지` | `--text-2` 테두리 |
| 오류·불가 | `✕` + 사유 | `danger` 테두리 + 아이콘 |

### 7.3 공사 빗금 (Hazard stripe)

- `caution`과 `--text-1`(paper) 또는 `--surface-0`(ink)을 45° 사선으로 번갈아 칠한 패턴. 폭 `6px` 간격.
- 공사 상태에만 쓴다: 공사 태그, 공사 중 선로 casing, 공사 모드 배너 표식, 공사 프로젝트 진행 막대.
- 넓은 면 장식으로 쓰지 않는다. 한 화면에서 빗금 면적은 표식 수준으로 제한한다.

### 7.4 아이콘

- 단색 선 아이콘, `1.75px` stroke, 끝 처리 square, 20px 격자.
- 철도 기호(역, 환승, 차량기지, 열차, 선로)는 지도 기호와 같은 모양을 축소해 쓴다.
- 아이콘 단독 버튼은 닫기, 실행 취소, 줌처럼 익숙한 명령에만 쓰고 accessible name과 tooltip을 제공한다.

## 8. 모드별 재질

| 모드 | 재질 | 모드 배너 표식 | 지도 위 작업 표현 |
| --- | --- | --- | --- |
| 관리 | 안내사인 | 먹 사각 `■` | 확정 시설 정상 렌더링, 선택 강조 |
| 기획 | 트레이싱지 + 파란 연필 | `info` 점선 사각 | 기획안 geometry를 `info` 점선으로, 기존 망은 낮은 대비 |
| 공사 | 도면 + 공사 표식 | 빗금 사각 | 작도 중 draft를 치수선과 사각 handle로, 공사 구간은 빗금 casing |

- 모드 배너는 지도 상단의 반전 띠(`--invert-bg`)에 `표식 + 모드 · 도구` 형식으로 쓴다. 예: `▨ 공사 · 노선 건설`.
- 기획 모드에서는 tool rail과 inspector 구획선을 `1px` 점선으로 바꾸어 "아직 확정이 아님"을 표면 전체로 알린다.
- 공사 모드의 확정 action bar에는 비용을 버튼 안이나 바로 옆에 Metric으로 표시한다.

## 9. 레이아웃 시스템

### 상시 HUD

상시 HUD는 화면 폭 전체를 덮는 띠를 만들지 않는다. 모서리에 붙은 **정보판(plate)** 과 왼쪽 가장자리 **레일**로 나누고, 그 사이로 지도가 보이게 한다. 배치는 `MOBILE_UX.md` §3을 따른다.

- **정보판(plate)**: 높이 `48`, `--surface-0` 면 + `1px --edge`. 칸 사이는 세로 `1px --rule`. 상세 표면이 있는 칸은 칸 전체가 버튼이다.
  - **재정 정보판(왼쪽 위)**: `자금 12,450억 ▲38.2억 | ● 75 안정`. 자금 칸 → 재정 관리, 만족도 칸 → 만족도 리포트. 일일 손익은 `▲`/`▼`와 신호 색, 만족도는 `●`(70 이상)·`△`(50 이상)·`✕`와 점수·문구를 함께 쓴다.
  - **시간 정보판(오른쪽 위)**: `날짜/시각 | 일시정지·재생 | 배속 | 뉴스 | 메뉴`. 일시정지 칸은 실행 중에 `‖`(일시정지), 정지 중에 반전 `▶`(재생, 직전 배속으로 재개)를 보인다. 배속 칸은 현재 배속(`×5`)을 보이고 누를 때마다 `×2 → ×5 → ×10 → ×100 → ×2` 순으로 바꾼다. 정지 중에 누르면 다음 배속으로 재개한다. 드롭다운은 쓰지 않는다.
  - 뉴스 칸은 새 소식 수를 반전 사각 배지로 보인다. 도움말은 메뉴 안에 둔다.
  - Compact(`<720px`)에서는 `자금`·`안정` 같은 보조 문구를 접고 수치·표식만 남긴다.
- **실행 취소·다시 실행**: 왼쪽 아래 엄지 영역의 `48` 사각 버튼 묶음.
- **Mode/tool rail(왼쪽 가장자리)**: 상단에 모드 전환(관리·기획·공사 세그먼트, 높이 `40`), 아래에 현재 모드 도구 목록(행 높이 `44`, 폭 `136`). 활성 도구는 반전 행 + 왼쪽 `4px` 표시 막대(반전 바탕 위 `--invert-fg`) + 도구명 + `aria-pressed="true"`.
  - 모드별 도구 목록은 우선순위 순서로 정의한다. 레일은 화면 높이 안에 들어가는 만큼만 보이고, 나머지는 뒤에서부터 `더보기` 패널로 옮긴다. 더보기 안의 도구가 활성이면 더보기 칸이 반전되고 그 도구 이름을 보인다.
  - 실행 취소·다시 실행과 더보기 패널은 레일 오른쪽에 붙인다(`--hud-left-clear`).
  - 정밀 지도 작업(draft 작도·편집) 중과 compact 화면에서는 compact rail(폭 `64`)로 줄인다. 상단에 현재 모드 반전 칸, 아래에 아이콘 + 짧은 도구명 세로 배치(행 높이 `44`). 모드 전환 세그먼트는 숨기고 현재 모드 칸을 눌러 펼친다.
- **모드 배너**: 위쪽 가운데. 두 정보판 사이에 들어가지 않으면 정보판 아래로 내린다.
- **Context inspector(오른쪽 아래)**: 선택 객체의 안내판. 폭 `316`, 주 행동은 오른쪽 아래 엄지 위치에 높이 `48`. 선택이 없으면 접힌다. 확장하면 시간 정보판 아래까지 올라가고 지도 컨트롤은 그 뒤로 숨는다.
- **Map controls(오른쪽, 시간 정보판 아래)**: 레이어, 범례를 `48` 사각 버튼 묶음으로 둔다. 펼침 패널은 바깥 탭과 Escape로 닫힌다. 테마 전환은 설정에만 둔다.
- 글자 확대로 정보판이 넘치면 잘리지 않고 줄바꿈한다. 아래 HUD는 정보판의 실제 아래쪽(`--hud-top`)을 기준으로 배치한다.

상시 HUD끼리 지도를 둘러싸는 두꺼운 프레임을 만들지 않는다. 지도 시야를 최대화하고, 상세 정보는 필요할 때 가장자리에서 들어오는 inspector 또는 sheet로 확장한다.

### 정보 계층

1. 현재 작업과 선택 대상
2. 확정에 필요한 비용·영향·유효성
3. 즉시 대응할 운영 경고
4. 핵심 운영 상태와 시간
5. 탐색 가능한 상세 통계와 기록

모든 KPI를 항상 노출하지 않는다. 상시 HUD는 의사결정에 필요한 최소 집합만 보여 주고 세부 분석은 inspector 또는 전용 화면에서 제공한다.

## 10. 선택, 도구, 모드 상태

선택과 활성 도구는 절대로 같은 표현을 쓰지 않는다.

| 대상 | 위치 | 표현 |
| --- | --- | --- |
| Mode | tool rail 상단, 모드 배너 | 세그먼트 반전 + 모드 재질 표식 |
| Tool | tool rail 행, 모드 배너 | 반전 행 + 왼쪽 표시 막대 + 도구명 |
| Selection | 지도 객체, inspector 헤더 | 먹색 외곽선 + 기준점 핀 + inspector 상단 띠 |

### 선택 객체

- 지도: 객체 바깥에 `2px` 바탕색 간격을 두고 `3px --text-1` 외곽선을 두른다. 그 위에 먹색 역삼각형 기준점 핀을 꽂는다. glow나 흐린 halo는 쓰지 않는다.
- inspector: 상단 띠(노선 색 또는 먹), 객체 종류 아이콘, Sign 크기 이름, 상태 태그, 노선 기호를 헤더에 고정한다.
- 선택이 바뀌면 지도와 inspector가 같은 프레임 안에서 함께 갱신되어야 한다.
- 가려진 객체나 겹친 객체는 선택 후보 목록을 제공하며 임의 선택하지 않는다.

### 활성 도구

- 지도: 커서 또는 터치 안내, 유효 지점 표시, 미리보기 geometry로 현재 동작을 예고한다.
- 도구 선택 직후 모드 배너 아래에 한 문장 다음 단계 안내를 표시한다.
- 완료, 취소, 도구 전환의 결과를 즉시 피드백한다. 도구가 켜진 채인지 추측하게 만들지 않는다.

### 초안·기획·공사·확정 상태

| 상태 | 지도 표현 |
| --- | --- |
| 작도 중 draft | `--text-1` `2px` 점선(6/4) + 정점마다 `8px` 사각 handle + 구간 길이 치수 레이블 |
| 유효한 스냅·연결점 | 먹색 실선 고리 `●` 표적 |
| 경고 포함 구간 | `caution` 구간 + `!` 삼각 표식 |
| 실행 불가 | `danger` `✕` 표식 + 짧은 이유 레이블 |
| 기획안 | `info` `3px` 점선 + 속이 빈 역 기호 |
| 공사 중 | 노선 색 선 + 빗금 casing, 역 기호 점선 테두리 |
| 확정·운행 | 노선 색 실선 + 바탕색 casing |

## 11. 지도 렌더링 규칙

- 지도 바탕은 인쇄 지도처럼 저채도·저대비로 둔다. 원본 타일의 색을 그대로 쓰지 않고 테마 토큰에 맞춰 무채색화한다. 구현 방식(타일 제공자 교체 또는 타일 필터)은 성능과 이용 약관을 검토해 정하되, 결과는 `4.1 지도 층` 토큰 범위에 맞춘다.
- 지형·철도 오버레이도 같은 무채색 처리를 따른다. 다른 레이어가 노선 색보다 눈에 띄면 안 된다.
- 구현: 타일 pane 하나에 CSS 필터를 건다(종이 `grayscale(1) sepia(.08) contrast(.62) brightness(1.14)`, 먹 `grayscale(1) invert(1) contrast(.6) brightness(.6)`). 지형·철도 타일도 같은 pane이라 함께 처리된다(`src/design/hud.css` 지도 바탕).
- 벡터 배경 레이어(행정 경계, 토지 이용)는 지도 층 토큰을 읽어 칠하고 테마를 바꾸면 `resetStyle()`로 다시 칠한다. 인구 밀도는 호박색 한 계열(`--signal-caution` → `--signal-caution-text`)과 불투명도로 표현하고 범례도 같은 범위를 쓴다.
- 지도 위 편집 안내(편집 점, 삭제 기준점, 철거 범위, 끊긴 구간, 기지 연결, 산악 구간·교량·터널 표시)는 `themeTokenColor`로 신호 토큰을 읽어 칠한다: 위험·철거 `--signal-danger`, 공사·지형 비용 `--signal-caution`, 편집 점·터널·기획 `--signal-info`, 연결 가능 `--signal-ok`. 노선 색 외의 고정 색을 새로 쓰지 않는다.
- 노선은 굵은 실선 + 바탕색 casing으로 그린다. 선택되지 않은 노선끼리 발광하거나 그림자를 갖지 않는다.
- 구현: `src/map/mapPalette.ts`의 `mapPalette()`가 테마 토큰(바탕·먹·신호색)을 `data-theme`별로 캐시해 렌더러(노선·역·기지·공사·기획)에 준다. 테마를 바꾸면 렌더러를 비우고 전체 갱신한다. 역명·운행계통 레이블과 역 누름 표시는 `src/design/hud.css` 지도 기호·레이블 구획에 있다.

### 역 기호

| 시설 | 기호 |
| --- | --- |
| 일반역 | `--surface-0` 원 + 노선 색 `2.5px` 테두리 |
| 환승역 | 더 큰 `--surface-0` 원 + `--text-1` `2.5px` 테두리. 떨어진 환승 역은 같은 테두리의 연결 막대로 잇는다 |
| 급행 정차역 | 일반역 기호 안에 `--text-1` 점 |
| 종착역 | 노선 끝의 직각 끝막대 + 역명 굵게 |
| 차량기지 | `--surface-0` 사각 + `--text-1` 테두리 + 안쪽 차고 아이콘 |
| 공사 중 시설 | 해당 기호의 테두리를 점선으로, 옆에 빗금 칩 |

- 선택한 운행계통은 전체 경로를 강조하고, 정차역은 이중 표식과 `정차` 역명 라벨, 통과역은 작고 비어 있는 점선 표식, 시·종착역은 마름모 표식과 `시·종착` 라벨로 구분한다. 노선 색만으로 정차 여부를 표현하지 않는다.
- 운행계통 정차역 지도 편집은 별도의 명시적 모드로 진입하며, 역 표식을 직접 선택해 정차/통과를 전환한다. 기점·종점은 잠긴 필수 정차역으로 유지하고, 지도 결과와 inspector 목록을 같은 프레임에서 동기화한다. 지도 편집의 `적용`은 계통 초안에만 반영하며 실제 운행계통 저장과 구분한다.

### 레이블과 LOD

- 역명 레이블은 바탕색 halo(`3px` stroke) 위 `--text-1` 글자로 쓴다. 노선 색 글자를 쓰지 않는다.
- 줌 수준에 따라 레이블과 세부 요소를 단계적으로 줄인다. 경고, 선택 표시, draft는 LOD에 의해 사라지지 않는다.
- 인구 밀도, 혼잡, 토지 이용 등 분석 레이어는 동시에 과도하게 겹치지 않게 하며 활성 레이어와 범례를 항상 표시한다. 분석 레이어가 켜지면 노선은 유지하되 지도 바탕 대비를 더 낮춘다.
- 선택 가능한 지도 객체의 터치 hit area는 시각 크기보다 넓게 잡는다.

## 12. 컴포넌트 원칙

### Buttons

| 종류 | 형태 | 용도 |
| --- | --- | --- |
| Primary | 반전 면(`--invert-bg`) + `--invert-fg` 글자, 800 | 표면당 하나의 주 행동 |
| Secondary | `--surface-0` 면 + `1.5px --text-1` 테두리 | 보조 행동 |
| Quiet | 테두리 없음, `--text-1` 글자, 눌림 시 `--surface-2` | 반복적 낮은 우선순위 |
| Destructive | `--signal-danger` 면 + `#FFFFFF` 글자 | 철거, 삭제, 운행 중지 확정 |

- 모든 버튼은 radius `2px`, 높이 `48`(compact `44`).
- 비용이 드는 행동은 버튼 라벨 오른쪽에 구획선과 Metric 비용을 붙인다. 예: `건설 확정 | 1,240억`.
- 비활성 버튼은 이유를 인접 문구로 설명한다.

### Panels and inspectors (안내판 패널)

구조:

1. 상단 띠 `4px`: 대상 노선 색, 노선이 없으면 `--text-1`
2. 헤더: 종류 아이콘 · Sign 이름 · 노선 기호 · 상태 태그 · 닫기
3. 구획: Section 레이블 + `1px --rule` 구획선 + 데이터 행
4. 액션 바: 상단 `2px --text-1` 강조선, 필요한 경우 sticky

- 패널 안에 또 다른 떠 있는 카드를 넣지 않는다.
- 스크롤 시 객체명과 액션 바는 필요한 경우 sticky로 유지한다.

### Data rows and tables

- `label | value | trend/status` 정렬을 반복한다. 값은 오른쪽 정렬 tabular.
- 혼잡, 수요, 수익처럼 비교가 핵심이면 작은 막대를 허용하되 숫자를 대체하지 않는다. 막대는 `--text-1` 면, 위험 구간만 신호 색.
- 여러 노선 비교는 카드 그리드가 아니라 노선 기호를 첫 열로 둔 표·정렬 목록으로 만든다.

### Inputs

- label은 항상 보이게 하고 placeholder를 label로 쓰지 않는다.
- 입력은 `--surface-1` 면 + 하단 `1.5px --text-1` 선(인쇄 서식의 기입란 형태). focus 시 전체 테두리 + focus 링.
- 조정 결과가 즉시 적용되면 현재 값과 영향을 함께 보여 준다.
- 색상 선택에는 swatch뿐 아니라 노선 기호 미리보기와 색상값을 제공한다.
- toggle은 이진 설정에만 사용한다. 행동 명령을 toggle처럼 보이게 하지 않는다.
- 세그먼트 컨트롤(모드, 배속, 테마)은 직사각형 칸을 이어 붙이고 선택 칸만 반전한다.

### Dialogs and confirmations

- 단순 정보는 inspector나 toast로 처리하고 modal을 남용하지 않는다.
- 확인 다이얼로그는 안내판 패널과 같은 구조를 쓰며, 뒤 배경은 `rgba(0,0,0,.32)` 단색 dim만 쓴다(blur 금지).
- 건설, 철거, 대출, 저장 삭제처럼 중요한 결정은 대상·비용·잔액·운영 영향·되돌릴 수 있는지를 한 화면에서 보여 준다.
- 위험 행동은 Destructive 스타일을 쓰되, 확인 문구 대신 구체적인 결과를 버튼에 쓴다. 예: `차량기지 철거`.
- 기존 부지의 차량기지 확장은 건설 Primary(반전)로 비용·잔액과 수용량·유지비 변화를 확인하며, 철거용 Destructive 확인과 구분한다. 확장 검토를 열 때 기지 inspector를 닫아 표면을 겹치지 않는다.

### Notifications

- toast: 완료나 비차단 정보. 반전 띠 형태, 짧게 자동 소멸.
- banner: 오류, 저장 실패, 네트워크 문제처럼 조치가 필요한 상태. 왼쪽 `4px` 신호 색 막대 + 아이콘 + 조치 버튼.
- alert queue: 도시 이벤트와 운영 경고. 심각도 표식(`!` 위험, `△` 주의, `i` 참고)과 발생 시점을 유지한다.
- 동일 사건을 toast, badge, modal로 중복 알리지 않는다.

### Full-screen workspace

분석, 통계, 자동 노선도, 저장 관리는 인쇄 문서처럼 만든다.

- 상단: 반전 제목 띠(제목 + 현재 게임 시간·일시정지 상태 + 닫기)
- 본문: 종이 바탕 위 표, 정렬 목록, 추세선. 카드 그리드 금지.
- 자동 노선도는 실제 노선도 관례(45° 격자, 노선 색 굵은 선, 환승역 먹 테두리)를 따르고 앱 테마를 따른다.

## 13. 모션과 피드백

안내판이 넘어가듯 짧고 단단하게 움직인다.

- 빠른 상태 전환: `100–140ms`
- panel 진입/이탈: `160–200ms`, 가장자리에서 슬라이드 + 즉시 불투명
- 지도 객체 선택 피드백: `120ms` 내 시작
- easing은 짧은 ease-out(`cubic-bezier(.2,.8,.2,1)`)만 쓴다. 탄성·바운스 금지.
- 장식용 looping animation은 금지한다. 열차 이동과 공사 진행처럼 시뮬레이션 상태를 표현하는 모션은 허용한다.
- `prefers-reduced-motion`에서는 slide를 즉시 전환으로 대체하고 pulse를 제거한다.
- 터치 입력, 스냅 성공, 건설 확정에는 시각 피드백을 기본으로 하고 사운드·진동은 설정 가능하게 한다.

## 14. 접근성과 품질 기준

- 일반 텍스트는 배경 대비 최소 `4.5:1`, 큰 텍스트와 비문자 핵심 UI는 최소 `3:1`. 두 테마 모두 검증한다.
- 터치 target은 최소 `44 × 44px`. 밀집 도구막대에서는 시각 요소가 작아도 hit area를 확보한다.
- focus-visible은 `2px --focus` 외곽선 + `2px` 바탕색 간격으로 표시하고 제거하지 않는다.
- 스크린 리더가 모드, 도구 활성 상태, 선택 객체, 진행률, 오류 원인을 읽을 수 있게 한다.
- landscape 640×360부터 대형 태블릿까지 잘림, 중첩, safe area 침범 없이 동작해야 한다.

## 16. UI 리뷰 체크리스트

- 지도가 여전히 가장 넓고 명확한 작업 표면인가?
- 화면에서 가장 채도 높은 것이 노선과 신호뿐인가?
- 현재 모드, 현재 도구, 선택 객체를 1초 안에 각각 말할 수 있는가?
- 모드의 재질(사인·트레이싱·도면)이 표면에서 드러나는가?
- 다음 액션과 그 결과·비용·위험이 확정 전에 보이는가?
- 컨테이너를 카드가 아니라 상단 띠, 구획선, 정렬로 만들었는가?
- 종이·먹 두 테마 모두에서 대비와 형태 문법이 유지되는가?
- 640×360 및 notch/safe-area 환경에서 핵심 액션이 가려지지 않는가?
- 터치 target, 대비, focus, 스크린 리더 상태가 충족되는가?
- 기존 UI를 닮았다는 이유만으로 남은 시각 패턴이 없는가?

규칙:

- 새 UI는 `dg-` 클래스와 토큰만 사용한다. 기존 `--color-*`, `--c-*` 변수와 기존 클래스는 참조하지 않는다.
- 색 토큰을 바꿀 때는 §4 표와 `tokens.css`를 함께 고친다. 테스트가 둘의 불일치를 막는다.
- 컴포넌트는 요소 선택자에 전역 스타일을 주지 않는다. 화면 단위로 기존 마크업을 `dg-` 컴포넌트로 교체하고, 교체가 끝난 화면의 기존 CSS는 그때 제거한다.
- 기존 CSS는 `legacy` layer 안에 있으므로 새 CSS의 보통 선언이 항상 이긴다. 단, layer 안의 `!important`는 밖의 `!important`보다 강하다. 기존 전역 `!important` 규칙이 `dg-` 요소에 걸리면 새 쪽에 `!important`를 더하지 말고 기존 규칙에서 `:where(:not([class*="dg-"]))`로 제외한다(`:where`로 감싸 기존 규칙끼리의 우선순위를 바꾸지 않는다).
- 새 마크업은 기존 클래스를 재사용하지 않는다. JS가 요소를 찾을 때는 id나 데이터 속성(`data-speed`, `data-layer`, `data-workspace-mode` 등)을 쓴다.
