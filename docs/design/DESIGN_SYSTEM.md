# Draw Gyotong Design System

## 1. 시각 문법

화면은 세 층으로 생각한다.

1. **Map field**: 노선, 역, 열차, 차량기지, 수요, 지형, 공사와 계획을 보여 주는 주 작업면
2. **Control rail**: 모드, 도구, 시간 제어처럼 자주 쓰며 짧게 유지되는 명령 영역
3. **Context surface**: 현재 선택 객체나 작업의 세부 정보, 검토, 확정을 위한 일시적 표면

컨테이너를 여러 장의 카드로 쪼개지 않는다. 하나의 연속된 패널 안에서 헤더, 구획선, 데이터 행, 그룹 레이블로 계층을 만든다. 배경색 변화는 깊이 표현이 아니라 실제 영역 분리 또는 상호작용 상태에만 사용한다.

## 2. 색상 토큰

아래 값은 새 UI의 기준 팔레트다. 실제 테마 토큰으로 정의해 사용하며 임의의 유사 색상을 늘리지 않는다.

| Token | Value | 용도 |
| --- | --- | --- |
| `--color-map-void` | `#071017` | 지도 밖, 최하단 배경 |
| `--color-surface-0` | `#0A141D` | 기본 HUD·패널 배경 |
| `--color-surface-1` | `#101C26` | 입력, 활성 구획, 상승 표면 |
| `--color-surface-2` | `#172630` | hover/focus/강조 표면 |
| `--color-border-subtle` | `#243641` | 기본 구획선 |
| `--color-border-strong` | `#3B5360` | 주요 경계와 선택 보조선 |
| `--color-text-primary` | `#E8F1F4` | 제목, 핵심 값 |
| `--color-text-secondary` | `#9FB1B9` | 설명, 보조 값 |
| `--color-text-muted` | `#687C85` | 비활성·낮은 우선순위 |
| `--color-accent` | `#25D0D6` | 활성 도구, 주 행동, 포커스 |
| `--color-accent-strong` | `#58F0E8` | 선택 객체의 최상위 강조 |
| `--color-accent-dim` | `#123F45` | accent 저강도 배경 |
| `--color-info` | `#4DA3FF` | 정보·계획 상태 |
| `--color-success` | `#49C987` | 정상·개통·완료 |
| `--color-warning` | `#F2B84B` | 주의·공사·비용 위험 |
| `--color-danger` | `#FF6577` | 오류·철거·파산 위험 |

### 색상 사용 규칙

- cyan/teal은 브랜드 장식이 아니라 **현재 조작 가능성**과 **활성 상태**에 집중한다.
- 노선 고유 색상은 시뮬레이션 데이터다. UI accent와 경쟁하지 않도록 작은 swatch, 선, 레이블에만 쓰며 텍스트 대비를 보장한다.
- 선택 객체는 `accent-strong` 윤곽 + 식별 마커 + 문맥 패널 헤더의 동일 식별자로 연결한다.
- 경고와 위험 색은 정상 상태에 사용하지 않는다. 의미 없는 빨강/초록 대비를 피한다.
- 상태는 색상만으로 구분하지 않는다. 아이콘, 레이블, 선 모양, 패턴 중 하나 이상을 병행한다.
- 그라디언트는 연속 수치 범례(예: 인구 밀도, 혼잡도)처럼 의미가 있을 때만 허용한다.

## 3. 타이포그래피와 숫자

기본 글꼴은 한국어 가독성이 높은 시스템 sans-serif를 사용한다.

```css
font-family: "Pretendard Variable", Pretendard, "Noto Sans KR", system-ui, sans-serif;
```

앱 패키지에 폰트를 포함하지 않았다면 네트워크 폰트 다운로드에 의존하지 않는다. 영문 상태 코드와 계기판 숫자는 동일 패밀리의 tabular numeral을 우선한다.

| 역할 | 크기 / 행간 | 굵기 | 용도 |
| --- | --- | --- | --- |
| Display | `20 / 26` | 700 | 전체 화면 또는 중요 다이얼로그 제목 |
| Section | `15 / 20` | 700 | 패널 제목, 선택 객체명 |
| Body | `13 / 18` | 500 | 기본 설명, 데이터 행 |
| Label | `11 / 14` | 600 | 필드명, 짧은 상태, 단위 |
| Micro | `10 / 12` | 600 | 범례, 보조 메타데이터 |
| Metric | `16 / 20` | 650, tabular | 자금, 시간, 주요 KPI |

규칙:

- 핵심 숫자는 단위와 함께 읽혀야 한다. `12,450억`, `4.2 km`, `03:40`, `87%`처럼 형식을 일관되게 한다.
- 동일 열의 숫자는 오른쪽 정렬하고 `font-variant-numeric: tabular-nums`를 사용한다.
- 영문 대문자 eyebrow는 섹션 식별에만 제한적으로 쓰며 본문을 대체하지 않는다.
- 정보를 작게만 만들어 밀도를 높이지 않는다. 중복 문구와 불필요한 컨테이너를 제거해 밀도를 만든다.

## 4. 간격, 형태, 깊이

4px 기반 스케일을 사용한다: `4, 8, 12, 16, 24, 32`.

- 컨트롤 내부: 보통 가로 `12`, 세로 `8`
- 데이터 행: 높이 `32–40`
- 패널 내부 구획: `16`
- 화면 가장자리 및 safe area: `max(12px, env(safe-area-inset-*)))`
- 관련 요소 간격은 `4–8`, 그룹 간격은 `12–16`으로 관계를 명확히 한다.

Radius는 구조를 표현할 때만 사용한다.

- 버튼·입력: `4px`
- 패널·다이얼로그: `6px` 이하
- 작은 태그: `2px`
- 완전한 pill은 단일 짧은 상태나 compact segmented control 외에는 금지한다.

그림자는 지도와 HUD를 분리하는 얕은 한 단계만 사용한다. glassmorphism, 다중 그림자, 장식용 blur, 상시 glow는 금지한다. 포커스와 긴급 알림의 짧은 pulse처럼 기능적 피드백에만 제한된 glow를 허용한다.

## 5. 레이아웃 시스템

### 상시 HUD

- **Status strip**: 자금, 일일 손익, 날짜·시간, 배속, 핵심 경보를 한 줄로 압축한다.
- **Mode/tool rail**: 관리·기획·공사 모드와 해당 도구를 한 영역에서 보여 준다. 현재 모드 밖의 도구는 숨기거나 명확히 비활성화한다.
- **Context inspector**: 선택 객체의 이름, 상태, 핵심 수치와 액션을 표시한다. 선택이 없으면 접힌다.
- **Map controls**: 줌, 레이어, 범례는 지도 가장자리의 작은 기능 그룹으로 둔다.

상시 HUD끼리 지도를 둘러싸는 두꺼운 프레임을 만들지 않는다. 중앙 지도 시야를 최대화하고, 상세 정보는 필요할 때 가장자리에서 들어오는 inspector 또는 sheet로 확장한다.

### 정보 계층

한 화면에서 우선순위는 다음과 같다.

1. 현재 작업과 선택 대상
2. 확정에 필요한 비용·영향·유효성
3. 즉시 대응할 운영 경고
4. 핵심 운영 상태와 시간
5. 탐색 가능한 상세 통계와 기록

모든 KPI를 항상 노출하지 않는다. 상시 HUD는 의사결정에 필요한 최소 집합만 보여 주고 세부 분석은 inspector 또는 전용 화면에서 제공한다.

## 6. 선택, 도구, 모드 상태

선택과 활성 도구는 절대로 같은 표현만 사용하지 않는다.

### 선택 객체

- 지도: 두 겹 윤곽 또는 halo가 아닌 **선명한 외곽선 + anchor marker**를 사용한다.
- inspector: 객체 종류 아이콘, 이름, 운행/공사 상태, 노선 swatch를 헤더에 고정한다.
- 선택이 바뀌면 지도와 inspector가 같은 프레임 안에서 함께 갱신되어야 한다.
- 가려진 객체나 겹친 객체는 선택 후보 목록을 제공하며 임의 선택하지 않는다.

### 활성 도구

- control rail: accent 배경/왼쪽 indicator, 명시적 도구명, `aria-pressed="true"`를 함께 사용한다.
- 지도: 커서 또는 터치 안내, 유효 지점 표시, 미리보기 geometry로 현재 동작을 예고한다.
- 지도 상단의 compact mode banner에 `공사 · 노선 건설`처럼 상위 모드와 도구명을 표시한다.
- 완료, 취소, 도구 전환의 결과를 즉시 피드백한다. 도구가 켜진 채인지 추측하게 만들지 않는다.

### 초안과 확정 상태

- 초안: cyan dashed line 및 반투명 면
- 유효한 스냅/연결점: solid cyan target
- 경고 포함: amber segment 또는 marker
- 실행 불가: danger marker + 짧은 이유
- 확정된 시설: 노선 고유 색상과 정상 렌더링

## 7. 컴포넌트 원칙

### Buttons

- 계층은 Primary, Secondary, Quiet, Destructive 네 종류만 둔다.
- 한 컨텍스트 표면에서 Primary는 하나를 원칙으로 한다.
- 아이콘 단독 버튼은 반복적이고 익숙한 명령(닫기, 실행 취소, 줌)에만 쓰며 accessible name과 tooltip을 제공한다.
- 모든 버튼을 pill로 만들지 않는다. 직사각형에 가까운 compact control을 기본으로 한다.
- 비활성 버튼은 이유를 인접 문구로 설명한다.

### Panels and inspectors

- 카드를 나열하지 말고 title bar + sections + data rows 구조를 사용한다.
- 구획은 1px divider, section label, 정렬 변화로 만든다.
- 패널 안에 또 다른 떠 있는 카드를 넣지 않는다.
- 스크롤 시 객체명과 핵심 action bar는 필요한 경우 sticky로 유지한다.

### Data rows and tables

- `label | value | trend/status`의 반복 정렬을 사용한다.
- 혼잡, 수요, 수익처럼 비교가 핵심이면 작은 bar/sparkline을 허용하되 숫자를 대체하지 않는다.
- 여러 노선 비교는 카드 그리드보다 표·정렬 목록을 우선한다.

### Inputs

- label은 항상 보이게 하고 placeholder를 label로 사용하지 않는다.
- 조정 결과가 즉시 적용되면 현재 값과 영향을 함께 보여 준다.
- 색상 선택에는 swatch뿐 아니라 노선명/색상값 또는 식별 레이블을 제공한다.
- toggle은 이진 설정에만 사용한다. 행동 명령을 toggle처럼 보이게 하지 않는다.

### Dialogs and confirmations

- 단순 정보는 inspector나 toast로 처리하고 modal을 남용하지 않는다.
- 건설, 철거, 대출, 저장 삭제처럼 중요한 결정은 대상·비용·잔액·운영 영향·되돌릴 수 있는지를 한 화면에서 보여 준다.
- 위험 행동은 danger 스타일을 사용하되, 확인 문구 대신 구체적인 결과를 버튼에 쓴다. 예: `차량기지 철거`.

### Notifications

- toast: 완료나 비차단 정보, 짧게 자동 소멸
- banner: 오류, 저장 실패, 네트워크 문제처럼 조치가 필요한 상태
- alert queue: 도시 이벤트와 운영 경고, 심각도와 발생 시점을 유지
- 동일 사건을 toast, badge, modal로 중복 알리지 않는다.

## 8. 지도 렌더링 규칙

- 기본 지도는 어두운 navy/charcoal 톤으로 낮은 대비를 유지해 운영 객체가 우선 보이게 한다.
- 노선은 배경과 충분히 구분하되 선택되지 않은 노선끼리 과도하게 발광하지 않는다.
- 역, 환승역, 급행 정차역, 종착역, 차량기지는 형태로도 구분한다.
- 줌 수준에 따라 레이블과 세부 요소를 단계적으로 줄인다. 중요한 경고와 선택 표시는 LOD에 의해 사라지지 않는다.
- 인구 밀도, 혼잡, 토지 이용 등 분석 레이어는 동시에 과도하게 겹치지 않게 하며 활성 레이어와 범례를 항상 표시한다.
- 선택 가능한 지도 객체의 터치 hit area는 시각 크기보다 넓게 잡는다.

## 9. 모션과 피드백

- 빠른 상태 전환: `100–160ms`
- panel 진입/이탈: `180–240ms`
- 지도 객체 선택 피드백: `120ms` 내 시작
- 선형 이동보다 짧은 ease-out을 기본으로 한다.
- 장식용 looping animation은 금지한다. 열차 이동과 공사 진행처럼 시뮬레이션 상태를 표현하는 모션은 허용한다.
- `prefers-reduced-motion`에서는 slide를 fade/즉시 전환으로 대체하고 pulse를 제거한다.
- 터치 입력, 스냅 성공, 건설 확정에는 시각 피드백을 기본으로 하고 사운드·진동은 설정 가능하게 한다.

## 10. 접근성과 품질 기준

- 일반 텍스트는 배경 대비 최소 `4.5:1`, 큰 텍스트와 비문자 핵심 UI는 최소 `3:1`을 목표로 한다.
- 터치 target은 최소 `44 × 44px`; 밀집 도구막대에서는 시각 요소가 작아도 hit area를 확보한다.
- focus-visible 윤곽을 제거하지 않는다. accent 색과 2px 이상의 외곽선으로 표시한다.
- 스크린 리더가 모드, 도구 활성 상태, 선택 객체, 진행률, 오류 원인을 읽을 수 있게 한다.
- landscape 640×360부터 대형 태블릿까지 잘림, 중첩, safe area 침범 없이 동작해야 한다.

## 11. 금지 목록

- SaaS dashboard 또는 admin panel식 전체 화면 카드 그리드
- 카드 남발, 카드 안의 카드, 모든 지표의 카드화
- 모든 버튼·탭·상태를 pill로 만드는 방식
- 큰 radius와 둥근 사각형을 브랜드 언어처럼 반복하는 방식
- 과도한 glassmorphism, blur, 반투명 레이어 중첩
- 의미 없는 gradient, neon glow, 장식용 빛 번짐
- 큰 hero 영역과 비어 있는 여백
- 하단 탭 중심의 일반 모바일 앱 구조
- 모드와 도구를 아이콘만으로 숨기는 방식
- 선택 상태를 색상 하나나 미세한 그림자 하나로만 표시하는 방식

## 12. UI 리뷰 체크리스트

- 지도가 여전히 가장 넓고 명확한 작업 표면인가?
- 현재 모드, 현재 도구, 선택 객체를 1초 안에 각각 말할 수 있는가?
- 다음 액션과 그 결과·비용·위험이 확정 전에 보이는가?
- 컨테이너를 카드가 아니라 구획과 정렬로 단순화할 수 있는가?
- 노선 색상, 상태 색상, accent가 서로 다른 의미를 유지하는가?
- 640×360 및 notch/safe-area 환경에서 핵심 액션이 가려지지 않는가?
- 터치 target, 대비, focus, 스크린 리더 상태가 충족되는가?
- 기존 UI를 닮았다는 이유만으로 남은 시각 패턴이 없는가?
