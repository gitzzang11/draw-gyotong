# Mobile Landscape UX

## 1. 범위와 목표

이 문서는 Draw Gyotong의 **모바일 가로화면** 경험을 정의한다. 사용자는 양손으로 기기를 잡고 엄지로 조작하며, 지도 탐색과 정밀한 철도 건설을 반복한다. 목표는 작은 화면에서 정보를 단순히 감추는 것이 아니라, 작업 단계에 맞춰 필요한 정보와 액션만 선명하게 배치하는 것이다.

우선순위는 다음과 같다.

1. 지도 조작의 연속성
2. 현재 모드·도구·선택 객체의 명확성
3. 실수 방지와 비용·영향 예측
4. 한 손을 놓지 않고 가능한 핵심 조작
5. 세부 정보로의 빠른 drill-down

## 2. 기준 viewport와 safe area

다음 환경을 최소 검증 범위로 삼는다.

| 등급 | CSS viewport 예시 | UX 대응 |
| --- | --- | --- |
| Compact landscape | `640×360`, `720×360` | 단일 inspector, 라벨 축약, 보조 상태 접기 |
| Standard landscape | `780×360`, `844×390` | 기본 3영역 HUD, 핵심 정보 상시 표시 |
| Large phone / foldable | `915×412`, `960×440` | inspector 확장, 보조 수치 추가 |
| Tablet landscape | `1024×600` 이상 | 더 넓은 inspector, 비교·목록 동시 표시 가능 |

- 모든 edge UI는 `env(safe-area-inset-top/right/bottom/left)`를 반영한다.
- OS gesture 영역에 주요 확정·취소 버튼을 직접 붙이지 않는다.
- `100dvh`를 기준으로 하며 주소창/시스템 UI 변화에도 핵심 컨트롤이 잘리지 않게 한다.
- 세로 방향도 같은 게임을 그대로 플레이한다. 배치는 §16을 따른다. 화면 방향은 `설정 → 화면 → 화면 방향`(자동·가로 고정·세로 고정)으로 정한다.

## 3. 기본 화면 골격

기본 플레이 화면은 화면 폭 전체를 덮는 띠 없이, 모서리 정보판과 가장자리 레일로 구성한다.

```text
┌──────────────────────────────────────────────────────────────┐
│[자금 12,450억 ▲38억│● 75]  [■ 관리·탐색]  [07:40│‖│×2│뉴스│≡]│ ← 정보판(읽기 위주)
│┌──────────┐                                            [레이어]│
││관리│기획│공사│                                               │
│├──────────┤                                                  │
││▶ 탐색     │             MAP FIELD                            │
││  노선 목록 │                              ┌─────────────────┐│
││  운영 현황 │                              │ Context         ││
││  …더보기  │                              │ inspector       ││
│└──────────┘                              │                 ││
│[↶][↷]   ← 왼손 엄지                       │  [주 행동 · 비용]││ ← 오른손 엄지
└──────────────────────────────────────────────────────────────┘
```

- 지도는 UI의 남은 공간이 아니라 화면 전체 바닥을 차지한다. 정보판 사이로도 지도가 보여야 한다.
- 위쪽 정보판은 자주 읽고 가끔 누르는 정보(자금, 만족도, 시간, 배속, 뉴스, 메뉴)를 담는다. 칸을 누르면 상세 표면을 연다.
- 왼쪽 레일은 현재 workspace mode에 필요한 도구만 보여 준다. 한 번에 5개 이하, 나머지는 `더보기`.
- 오른쪽 아래는 inspector와 확정 행동, 왼쪽 아래는 되돌리기·취소 자리다.
- Context inspector는 기본적으로 화면 짧은 변의 `32–38%` 이내를 차지하며 선택이 없을 때 접힌다.
- compact 화면에서 tool rail과 inspector를 동시에 크게 펼치지 않는다.

## 4. 엄지 도달성과 컨트롤 배치

양손으로 가로 기기를 잡았을 때 엄지가 편하게 닿는 곳은 좌우 가장자리의 아래쪽 절반이다. 위쪽 가운데는 가장 닿기 어렵다.

| 위치 | 담는 것 |
| --- | --- |
| 왼쪽 가장자리(레일) | 모드 전환, 도구 선택 |
| 왼쪽 아래 | 실행 취소·다시 실행, draft 되돌리기·취소 |
| 오른쪽 아래 | inspector 주 행동, 건설·변경 확정(비용 포함) |
| 왼쪽 위 | 재정·만족도 정보판 |
| 오른쪽 위 | 시간 정보판(일시정지·배속·뉴스·메뉴), 그 아래 지도 컨트롤 |
| 위쪽 가운데 | 모드 배너, 한 줄 안내(읽기 전용, 누르는 요소를 두지 않는다) |

- 빈도가 높은 도구 전환, 취소, 확정은 좌우 하단 엄지 영역에 둔다.
- 시간 조작은 오른쪽 위 시간 정보판에 고정하되 지도 zoom과 분리한다. 펼침 목록 없이 한 번 탭으로 동작한다(일시정지·재생 토글, 배속 순환).
- 주 행동 버튼과 HUD 정보판의 높이는 `48`, 도구 행과 보조 버튼은 `44` 이상으로 한다.
- 호버, 마우스 오른쪽 클릭, title tooltip에만 의존하는 정보나 기능을 두지 않는다.
- 위험 액션은 가장자리의 반복 탭 위치에서 한 단계 안쪽에 두고, 일상 액션과 충분히 떨어뜨린다.
- 정밀 지도 작업 중에는 tool rail을 compact 상태로 줄여 실수로 UI를 누르는 영역을 최소화한다.
- 노선 경로를 드래그하는 동안 손가락이 상단 또는 하단 HUD에 접근하면 해당 정보판·버튼 묶음만 가장자리까지 남은 거리에 비례해 투명해지고 화면 밖으로 물러난다. 드래그 종료·취소 시 즉시 복원하며, 드래그 시작 전의 일반 HUD 조작에는 적용하지 않는다.
- 손가락이 가리는 위치를 고려해 스냅 지점, 거리, 비용 tooltip은 접촉점의 위쪽 또는 반대편에 띄운다.

## 5. 핵심 상태 모델

사용자는 언제나 다음 세 질문에 답할 수 있어야 한다.

1. 나는 어느 workspace mode에 있는가? — 관리 / 기획 / 공사
2. 지금 지도 탭은 무엇을 하는가? — 탐색 / 노선 / 연장 / 편집 / 철거 / 재연결 / 분기 / 병합 / 역 / 환승 / 기지 / 급행 정차
3. 무엇이 선택되어 있는가? — 노선 / 역 / 열차 / 차량기지 / 계획 / 공사 프로젝트

상위 모드, 활성 도구, 선택 객체는 각각 다른 위치와 형태로 표현한다.

- **Mode**: tool rail 상단 세그먼트 반전 + 모드 재질 표식(사인·트레이싱·도면)
- **Tool**: 레일 폭을 꽉 채운 반전 행(pressed control) + 지도 위 compact mode banner
- **Selection**: 지도 객체 먹색 외곽선/기준점 핀 + inspector 상단 띠와 header

도구가 활성화된 상태에서 객체를 탭했을 때는 선택보다 도구 동작을 우선하되, 대상이 무엇인지 preview에서 분명히 보여 준다. 단순 탐색 도구에서는 탭이 선택, 빈 지도 탭이 선택 해제로 동작한다.

## 6. 지도 제스처

### 기본 제스처

| 제스처 | 탐색 상태 | 건설·편집 상태 |
| --- | --- | --- |
| 한 번 탭 | 객체 선택 또는 겹침 후보 | 지점/대상 추가, 사전 preview |
| 빈 지도 드래그 | pan | 명시적 handle 외에는 pan 유지 |
| 두 손가락 pinch | zoom | zoom 유지, draft 보존 |
| 두 손가락 drag | pan | pan 유지, draft 보존 |
| 객체/handle drag | 선택 객체 이동 없음 | 명시된 편집 handle만 이동 |
| 길게 누르기 | context 정보 또는 후보 | 정밀 loupe/지점 조정, 삭제 실행 금지 |

- single-finger pan을 막는 도구는 최소화한다. 필요한 경우 화면에 `두 손가락으로 지도 이동` 안내를 즉시 표시한다.
- 길게 누르기에 핵심 기능을 독점 배치하지 않는다.
- double tap은 zoom과 건설 입력이 충돌하므로 건설 모드에서 필수 제스처로 사용하지 않는다.
- draft 중 zoom/pan 후에도 현재 단계와 geometry가 유지되어야 한다.

### Hit target과 겹침

- 지도 객체의 최소 터치 hit area는 `44×44px`에 준한다.
- 겹친 노선·역·시설이 있으면 가까운 하나를 임의 실행하지 않고 후보 chooser를 띄운다.
- 선택 후보는 거리순만이 아니라 객체 종류와 현재 도구 적합성을 함께 고려한다.
- 후보 chooser에서 노선 색상, 객체 유형, 이름, 상태를 표시한다.

## 7. 작업별 흐름

### 7.1 지도 탐색과 객체 관리

1. `관리 · 탐색` 상태로 시작한다.
2. 객체 탭 시 지도 선택 표시와 context inspector가 동시에 열린다.
3. inspector 첫 화면에는 이름, 유형, 운행/공사 상태, 핵심 KPI, 가장 가능성 높은 액션을 보인다.
4. 상세 통계나 설정은 inspector 내부 section 또는 전용 전체 화면으로 연다.
5. 다른 객체를 탭하면 inspector를 닫았다 다시 열지 않고 내용만 교체한다.

객체별 필수 정보와 액션:

| 객체 | 우선 정보 | 주요 액션 |
| --- | --- | --- |
| 노선 | 이름/색상, 운행 상태, 배차, 혼잡, 대기, 수익 | 이름·색상, 운임, 일반/급행, 일시중지, 차량, 연장·편집 |
| 역 | 이름, 운영/공사 상태, 승객·수요, 연결 노선, 환승 | 이름 변경, 수요 원인 확인, 환승 확인, 철거 |
| 열차/편성 | 소속 노선, 형식, 차량 수, 수용력, 상태 | 편성 구입·배치, 조정·회수 |
| 차량기지 | 운영/공사 상태, 수용력, 사용량, 연결 노선 | 확장, 연결 확인, 철거 |
| 공사 | 종류, 진행률, 예상 완료, 개통 조건 | 현장 보기, 개통 검토, 취소 가능한 경우 취소 |
| 기획안 | 상태, 우선순위, 비용, 예상 효과, 포함 항목 | 편집, 비교, 복제, 건설 전환, 삭제 |

### 7.2 노선·역·기지 건설

건설은 `도구 선택 → 지도 입력 → 미리보기 → 검토 → 확정 → 결과` 흐름을 따른다.

- 도구 선택 직후 지도 위에 한 문장의 다음 단계 안내를 표시한다.
- 각 탭마다 snapping 대상, 예상 연장 길이, 누적 비용과 유효성을 갱신한다.
- draft의 각 vertex는 잡을 수 있는 handle로 표시하되, 지도 축척에 맞춰 과밀해지면 중요 handle만 노출한다.
- 취소와 한 단계 되돌리기를 항상 제공한다. 시스템 뒤로가기는 우선 현재 draft 한 단계를 해제한다.
- 확정 전 검토에는 총 길이, 역/기지 연결, 기본 건설비, 지형 영향, 예상 기간, 잔액, 경고를 포함한다.
- 실행 불가한 경우 confirm만 비활성화하지 말고 지도와 검토 영역에 이유를 표시한다.
- 확정 후 결과를 지도에서 보여 주고, 공사 프로젝트 또는 즉시 개통 상태로 자연스럽게 연결한다.

### 7.3 연장·분기·병합·재연결·환승

- 첫 단계에서 기준 노선/역을 선택하도록 하며 선택 대상을 inspector 헤더에 고정한다.
- 접속 가능한 대상만 강조하고 나머지는 낮은 대비로 둔다.
- 동일 위치에 여러 연결 후보가 있으면 노선명과 방향을 표시하는 chooser를 사용한다.
- 기존 운행에 미치는 영향(단절, 운행 중지, 환승 변화)을 확정 전에 명시한다.
- 취소 시 기존 네트워크는 변하지 않아야 하며 임시 blueprints만 제거한다.

### 7.4 운영 관리

- 노선의 배차, 혼잡, 대기, 운임, 차량 수는 가능한 한 같은 inspector에서 비교 가능하게 한다.
- 조정 전에 예상 수요·수익·혼잡 변화를 preview로 제공하되 자동 적용하지 않는다.
- 일반/급행 계통과 급행 정차역은 노선도와 지도에서 형태로 구분한다.
- 운행계통의 `지도에서 정차역 설정` 모드에서는 경로 위 역을 최소 `44×44px` hit area로 직접 터치해 정차/통과를 바꾸고 inspector 체크 목록을 즉시 동기화한다. 하단에는 정차·통과 수와 `적용`·`취소`를 고정하며, 기점·종점은 변경할 수 없는 필수 정차역으로 안내한다.
- 운행 일시중지는 즉시 영향 범위를 알려 주고 명시적으로 확인한다.
- 운영 분석은 조언과 실행을 분리한다. 제안의 action은 관련 객체/도구로 이동하며 자동으로 자금이나 시설을 변경하지 않는다.

### 7.5 시간과 시뮬레이션

- 일시정지와 현재 배속은 항상 보인다.
- 다이얼로그나 전체 화면 분석을 열었다고 자동 일시정지하는지 여부를 일관되게 정하고 상태를 표시한다.
- 파산 위험, 공사 완료, 심각한 네트워크 오류처럼 즉시 대응할 사건은 배속 제어 가까이에 표시한다.
- 배속 버튼은 누를 때 현재 선택 상태가 명확하게 바뀌며 숫자나 텍스트를 병행한다.

### 7.6 재정, 뉴스, 분석, 통계

- 자금과 일일 순수익은 상시 HUD에, 대출·상환·세부 내역은 전용 표면에 둔다.
- 금융 액션은 실행 금액, 실행 후 잔액/부채, 이자 영향을 확정 전에 보여 준다.
- 뉴스는 수요 기회와 비용·운영 변화를 구분하고 유효 기간과 영향을 표시한다.
- 분석 제안은 긴급/주의/참고 심각도, 원인, 대상, 예상 효과, 이동 action을 갖는다.
- 통계는 카드 모음보다 비교 가능한 정렬 목록, 표, 추세를 우선한다.

### 7.7 저장과 세션

- 자동 저장 상태는 방해되지 않는 작은 상태로 표시하되 실패 시 banner로 승격한다.
- 저장 슬롯 삭제, 새 게임으로 덮어쓰기, 불러오기는 세이브 이름과 마지막 저장 시점을 확인시킨다.
- 앱이 background로 전환되거나 회전해도 draft와 선택 상태가 예기치 않게 사라지지 않게 한다.

### 7.8 화면 테마

- 기본 테마는 밝은 종이 지도(`paper`)이며 `설정 → 화면 → 지도 테마`에서 어두운 먹 지도(`ink`)로 바꿀 수 있다.
- 테마는 기기 설정으로 저장하며 세이브 슬롯, 새 게임, 불러오기에 영향을 주지 않는다.
- 전환은 즉시 적용하고 draft, 선택, 열린 표면, 지도 시야, 시뮬레이션 진행 상태를 유지한다.
- 테마 전환은 설정 화면에만 두고 상시 HUD에 바로가기를 두지 않는다.

## 8. 패널, sheet, 전체 화면의 선택 기준

| 표면 | 사용 조건 | 예시 |
| --- | --- | --- |
| Compact inspector | 지도와 함께 판단해야 하는 객체 정보 | 역, 노선, 기지, 공사 선택 |
| Expanded inspector | 지도 문맥을 유지한 채 여러 설정 조정 | 노선 운영, 차량 편성 |
| Center confirmation | 짧고 중요한 확정 | 건설, 철거, 대출 |
| Full-screen workspace | 비교·편집·대량 정보가 핵심 | 분석, 통계, 자동 노선도, 저장 관리 |
| Toast/banner | 결과 또는 복구 가능한 오류 | 저장 완료, API 실패, 실행 취소 |

- 같은 시점에 inspector와 modal을 여러 겹 쌓지 않는다.
- 새 표면을 열기 전 뒤로가기 동작을 정의한다.
- 전체 화면 workspace에서도 현재 게임 시간/일시정지 상태를 확인할 경로를 둔다.
- 소프트 키보드가 열린 동안 입력 필드와 저장/확정 action이 함께 보이도록 scroll/pan 한다.

## 9. 시스템 뒤로가기와 닫기 우선순위

Android back 및 화면 닫기는 다음 순서로 처리한다.

1. 열린 선택 후보, tooltip, 메뉴 닫기
2. modal confirmation 닫기
3. 현재 draft의 마지막 단계 되돌리기
4. 활성 도구를 탐색으로 전환
5. expanded inspector를 compact로 접기
6. compact inspector 닫고 선택 해제
7. full-screen workspace에서 지도 복귀
8. 게임 종료 의도 확인

뒤로가기 한 번에 여러 단계가 사라지지 않게 한다. 취소해도 비용이 발생하거나 저장 상태가 바뀌지 않아야 한다.

- 구현: 안드로이드 앱의 뒤로가기는 `MainActivity`가 먼저 `window.__drawGyotongBack()`(`main.ts` `handleSystemBack`)을 부른다. 위 순서대로 한 단계만 닫고(펼친 모드 목록·더보기·레이어 메뉴 → 맨 위 대화상자 → 전체 화면 → 정차역 지도 편집·작도 중인 검토 → 켜진 도구를 탐색으로 → 펼친 정보창 접기 → 정보창·노선 목록·노선 설정 상자 닫기), 닫을 것이 없으면 `뒤로 버튼을 한 번 더 누르면 게임을 종료합니다` 토스트를 띄운다. 2초 안에 다시 누르면 저장 후 앱을 닫는다. 시작 화면은 새 게임·불러오기 안내판부터 닫는다. 표면은 각자의 닫기 버튼을 눌러 닫으므로 닫을 때의 정리·저장 경로가 같다.

## 10. 가로화면 정보 밀도 규칙

- 한 줄에 label과 value를 배치하되 의미 단위가 둘 이상 겹치면 줄을 분리한다.
- 상시 영역에는 가장 중요한 4–6개 상태만 둔다. 나머지는 탭/확장으로 접근한다.
- 긴 한국어 레이블은 의미를 유지하는 표준 축약어를 정해 일관되게 사용한다.
- horizontal scroll은 노선 비교 표처럼 축이 명확할 때만 허용한다. 핵심 action bar에는 사용하지 않는다.
- vertical scroll 영역 안에 또 vertical scroll 영역을 만들지 않는다.
- landscape 높이가 짧을수록 제목·장식·설명부터 줄이고 action과 상태는 유지한다.
- 빈 여백으로 고급스러움을 만들지 않는다. 정렬, 대비, divider, 타이포그래피로 계층을 만든다.

## 11. 오류, 경고, 파괴적 액션

- 입력 오류는 발생 위치와 해결 방법을 함께 표시한다.
- 네트워크·지도 데이터 실패는 게임 상태 손실과 구분하며 재시도 경로를 제공한다.
- 파괴적 action은 정상 Primary와 떨어뜨려 배치하고 danger 색 + 구체적 동사를 사용한다.
- 비용이 드는 action은 버튼 또는 바로 인접한 영역에 비용을 표시한다.
- 철거, 대규모 건설, 대출 등은 영향 대상과 되돌릴 수 있는지를 확인한다.
- 오래 걸리는 작업은 진행 상태와 취소 가능 여부를 표시하고 중복 실행을 막는다.

## 12. 접근성 및 기기 대응

- 모든 핵심 액션은 터치 target `44×44px` 이상을 보장한다.
- 시스템 글자 크기 `125%`에서도 잘림 없이 작동해야 하며, compact HUD는 필요한 경우 값을 줄바꿈하거나 보조 항목을 접는다.
- 색각 이상에서도 노선, 경고, 선택을 형태·텍스트로 구분한다.
- screen reader에는 현재 mode/tool, 선택 객체명, 유효/오류 상태, 진행률을 live region 남용 없이 알린다.
- 진동과 소리는 보조 피드백이며 끌 수 있어야 한다.
- reduced motion, battery mode에서 정보와 조작 가능성은 동일하게 유지한다.
- 화면 밝기가 낮고 야외 반사가 있는 상황에서도 주요 텍스트와 선택 윤곽이 읽혀야 한다. 종이·먹 두 테마 모두에서 검증한다.

## 13. 성능과 반응성

- 터치 후 시각 피드백은 `100ms` 이내 시작을 목표로 한다.
- drag 중 비용·길이 계산이 무거우면 프레임 단위로 throttle하되 손가락과 geometry는 즉시 따라야 한다.
- 큰 네트워크에서 LOD로 레이블과 열차 렌더링을 줄여도 선택, 경고, draft는 유지한다.
- inspector 갱신 때문에 지도 pan/zoom이 끊기지 않도록 렌더링 경로를 분리한다.
- 느린 계산에는 이전 값을 조용히 유지하지 말고 계산 중 상태를 표시한다.

## 14. 모바일 UX 검증 시나리오

각 UI 변경은 최소한 다음을 수동 검증한다.

1. 640×360에서 새 노선을 그리고 비용 검토 후 취소·확정한다.
2. notch 또는 비대칭 safe area 환경에서 좌우 UI가 가려지지 않는다.
3. 노선/역/차량기지가 겹친 지점에서 원하는 객체를 선택한다.
4. 선택 객체가 있는 상태에서 도구를 전환하고 mode/tool/selection을 혼동하지 않는다.
5. draft 중 pinch zoom과 pan 후 작업을 이어 간다.
6. 건설 불가 사유와 해결 방법을 확인한다.
7. Android back으로 overlay와 draft가 정의된 순서대로 닫힌다.
8. 글자 크기 125%, reduced motion, 진동 off에서 핵심 흐름을 완료한다.
9. 대출, 철거, 운행 일시중지에서 영향과 결과를 확인한 뒤 실행한다.
10. 저장 실패 후 게임 상태를 잃지 않고 재시도한다.
11. 노선 draft 중 종이↔먹 테마를 전환해도 draft와 선택이 유지되고 두 테마에서 대비가 충분하다.

## 15. 모바일 UX 안티패턴

- 화면을 상단 bar, 좌측 sidebar, 우측 카드 열로 고정해 지도를 작은 사각형으로 만드는 것
- 일반 모바일 앱의 bottom navigation을 게임의 mode/tool 구조에 억지로 적용하는 것
- 모든 정보를 bottom sheet로 보내 지도와 선택 대상의 연결을 끊는 것
- gesture만 있고 화면상 대안이나 안내가 없는 것
- 작은 아이콘만 밀집시켜 높은 정보 밀도라고 간주하는 것
- 도구 활성화 여부를 버튼 색의 미세한 차이로만 보여 주는 것
- 확인 없이 탭 한 번으로 철거·대출·대규모 비용 지출을 실행하는 것
- modal 위에 modal, sheet 위에 dialog를 겹치는 것
- 긴 애니메이션과 glow로 조작 피드백을 대신하는 것

## 16. 세로 화면

폰을 세워 한 손으로 잡으면 엄지가 닿는 곳은 화면 아래쪽이다. 가로 화면의 영역 규칙(§3·§4)은 그대로 두고, 누르는 것을 아래로 모은다. 시안: `docs/design/prototype/portrait.html`.

| 등급 | CSS viewport 예시 | 대응 |
| --- | --- | --- |
| Compact portrait | `360×640`, `360×740` | 정보판 두 줄(시간 정보판이 둘째 줄 오른쪽), 도구 4칸 + 더보기 |
| Standard portrait | `375×812`, `390×844`, `412×915` | 정보판 한 줄, 도구 4–5칸 + 더보기 |

```text
┌──────────────────────────┐
│[58,676억│●  ] [06:00▶×1뉴스≡]│ ← 정보판(자금 아래 순익, 만족도 표식 아래 점수)
│      [■ 관리·탐색]    [◱]│
│                          │
│          지도            │
│┌────────────────────────┐│
││ ═══ 손잡이              ││ ← 정보창·검토(레일 위 전체 폭)
││ 유스퀘어       ● 운영 ✕││
││ [보조]    [주 행동·비용]││
│└────────────────────────┘│
│[↶][↷]                     │ ← 실행 취소(검토 중에는 검토 창이 그 위)
│[관리][탐색][노선][현황][⋯]│ ← 도구 레일(가로)
└──────────────────────────┘
```

- 판단 기준은 기기 방향이 아니라 화면 비율이다(`orientation: portrait`, 세로가 가로 이상). 태블릿·창 크기 변화도 같은 규칙.
- **정보판**: 엇갈리지 않게 줄마다 화면 폭을 채운다. 한 줄에 들어가면 재정 정보판(자금 아래 순익, 만족도 표식 아래 점수)이 시간 정보판 바로 옆까지 늘어난다. 못 들어가면(앱에 글꼴을 넣지 않아 기기 글꼴에 따라 폭이 다름) 첫 줄은 재정 정보판 + 레이어 버튼, 둘째 줄은 칸을 고르게 나눈 시간 정보판으로 둔다(노선 설정 상자는 전체 폭). 판단은 늘리기 전 원래 폭으로 하고, 정보판 크기나 글자(자금·시각)가 바뀔 때마다 다음 프레임에 다시 맞춘다.
- **도구 레일**: 화면 아래 가로. 왼쪽 반전 칸이 현재 모드(누르면 위로 모드 목록), 오른쪽 상자에 도구를 화면 폭에 들어가는 만큼(칸 최소 56px) 두고 나머지는 `더보기`(레일 위 오른쪽에 펼침).
- **실행 취소**: 레일 위 왼쪽. 아래쪽 작업 막대(철거 범위 등)는 그 오른쪽.
- **정보창**: 레일 위 전체 폭. 처음에는 화면 높이의 46%까지, 위쪽 손잡이를 누르거나 위로 밀면 정보판 아래까지 펼치고, 다시 누르거나 아래로 밀면 접는다. 열 때마다 접힌 상태에서 시작한다. 주 행동은 맨 아래 줄.
- **건설·철거 검토**: 정보창 자리지만 실행 취소 줄 위에 둬서 한 단계 되돌리기를 가리지 않는다. 위쪽 노선 설정 상자와 함께 지도를 좁히므로 높이는 화면의 36%(높이 800 미만 화면은 30%)까지, 본문만 스크롤하고 확정 줄은 고정한다. 경고가 본문 아래로 밀릴 수 있어 펼친 상태에서도 머리글에 `△ 주의 n`·`✕ 확인 n` 개수를 보인다. 접기는 머리글의 접기 버튼(손잡이 없음).
- **지도 시야**: 방금 누른 대상이나 그린 초안이 열린 정보창·검토에 가려지면, 손을 뗀 뒤 정보창 위에 남은 지도(정보판·모드 배너·노선 설정 상자 아래) 가운데로 옮긴다. 누르고 있는 동안(그리는 중)과 탐색 도구로 지도를 끌어 옮긴 경우에는 옮기지 않는다. 도시 남쪽 끝도 정보창 위로 올려 볼 수 있게 세로 화면에서는 지도 이동 범위를 남쪽으로 도시 높이의 25% 더 허용한다.
- **노선 설정 상자**: 모드 배너 아래 전체 폭(레이어 버튼 자리는 비움). 지도를 덜 가리게 머리글만 두고 펼치기 버튼으로 연다. 도구 안내는 그 아래에 뜬다.
- **대화상자**: 화면 아래쪽에 붙여(아래에서 올라옴) 확정·취소 버튼이 엄지에 닿게 한다.
- **전체 화면**: 두 열(목록·상세, 캔버스·설정)을 한 열로 쌓는다. 노선도는 캔버스 아래에 설정. 제목 띠의 보조 문구(분석 기준 등)는 제목 아래 둘째 줄로 내려 제목이 잘리지 않게 한다.
- **메인 화면**: 메뉴 열을 아래쪽 전체 폭에 두고 위로 노선이 그려지는 지도를 보인다. 새 게임·불러오기 안내판은 화면 전체.
- **표면 모션**: 붙은 가장자리 기준. 정보창·검토·더보기는 아래에서 올라오고 내려가며, 노선 설정 상자는 위에서 내려온다.
- 돌려도 그리던 노선, 선택, 열린 표면, 지도 시야, 시간 흐름을 그대로 둔다(§7.7).

### 화면 방향 설정

| 값 | 동작 |
| --- | --- |
| 자동(기본) | 폰의 자동 회전 설정을 따른다. 자동 회전이 꺼져 있으면 폰이 고정한 방향을 유지한다(안드로이드 `fullUser`). |
| 가로 고정 | 폰 설정과 상관없이 가로(뒤집힌 가로 포함, `sensorLandscape`) |
| 세로 고정 | 폰 설정과 상관없이 세로(`sensorPortrait`) |

- 기기 설정으로 저장하며 세이브에 넣지 않는다. 안드로이드 앱은 `MainActivity`가 웹의 `DrawGyotongNative.setOrientation`을 받아 적용하고 앱 저장소에도 기억해, 다음 실행 때 웹 화면이 뜨기 전에 먼저 적용한다. 설치한 웹 앱·브라우저는 Screen Orientation API로 잠그며, 잠글 수 없는 브라우저에서도 화면 비율에 맞는 배치로 그대로 플레이한다.
